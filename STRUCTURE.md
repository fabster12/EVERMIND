# Folder structure

Every file and folder in this repository, with what it is and why it is
there. `src/` has its own [`src/STRUCTURE.md`](src/STRUCTURE.md) going a
level deeper.

**The one-line version:** `src/` is the thing we are building; everything
else is about building it.

---

## Top level

```text
EVERMIND/
├── src/                    THE PROJECT - the agent, its data, its specs. See src/STRUCTURE.md
├── docs/                   Finished documents people read. Generated or converted, not drafted here
├── notes/                  Working material - the brief, lab notes, course guides
├── scratch/                Drafts and working notes. Committed, but nothing here is authoritative
├── presentation/            8-min VP pitch video - plan and prompts, not the Phase 1 deck
├── tools/                  Scripts that generate everything in docs/ and src/fixtures/
│                           (and the two share zips, into a dist/ it creates on demand)
│
├── START-HERE.md           Setup, in order: uv, .env, the git helpers. Read this first
├── pyproject.toml          Dependencies and the ADK pin. uv.lock beside it is committed
├── README.md               Start here: what EverMind is, how to rebuild it, who owns what
├── STRUCTURE.md            This file
├── TODO.md                 Open items with the reasoning, so tomorrow-you knows why
├── .gitignore              What never reaches GitHub: *.docx, dist/, 36 MB of course HTML
└── .env.example            Variable NAMES only, never values. Copy to .env locally
```

## `tools/` — the generators

```text
tools/
├── fedex_layout.py             Shared FedEx branding: colours, banner, headings, tables, callouts.
│                               Every builder imports this. Editing it changes every document at once
├── build_fixtures.py           Writes src/fixtures/*.json from one seed. Deterministic - same seed, same bytes
├── build_diagram.py            Draws docs/architecture.png. Rendered at 3x and downsampled for clean text
├── build_design_evermind.py    The 7-page design document, into docs/gate1/
├── build_summary_group1.py     The 3-page instructor summary, into docs/gate1/
├── build_review_benchmark.py   The 2-page proposal review, into docs/reviews/
│
└── packaging/                  Turning the above into something shareable
    ├── to_pdf.ps1              Converts every .docx under docs/ to PDF by driving Word over COM.
    │                           Keeps Word invisible and always quits it, so no orphan process holds a lock
    ├── build_packages.py       Builds both share zips, then checks integrity and scans for credentials
    ├── docs-package-readme.md  Becomes README.md inside the Docs zip. Written for a reviewer
    └── tech-package-readme.md  Becomes README.md inside the Tech zip. Written for a developer
```

Every script overwrites its own output, so re-running is always safe.

## The share packages

Not a committed folder. `python tools/packaging/build_packages.py` creates
`dist/` on demand and writes two zips into it:

| Zip | For | Holds |
| --- | --- | --- |
| `EverMind-Group1-Docs.zip` | colleagues and reviewers | the PDFs, the plan, the specs. Nothing to run |
| `EverMind-Group1-Tech.zip` | whoever picks up the code | fixtures, build scripts, specs, `.env.example` |

`dist/` is gitignored entirely: the zips rebuild in seconds, and a stale zip
in git is worse than no zip. The two readmes that go *inside* them are
hand-written source, so they live in `tools/packaging/` with the script that
uses them.

## What is deliberately not in git

| Pattern | Why |
| --- | --- |
| `.env`, `.env.*` | Credentials. `.env.example` carries names only and **is** committed |
| `*.docx`, `~$*` | Generated by `tools/`; the `.pdf` and `.md` are the readable copies |
| `notes/reference/` | 36 MB of vendor course material we may not redistribute |
| `src/out/` | Pipeline output, regenerated every run |
| `dist/` | Share packages, rebuilt on demand in seconds |
| `__pycache__/`, `.venv/` | Python build artifacts |

Result: **about 1.7 MB reaches GitHub**, out of 40 MB on disk.

## Where things get written

Useful when something lands somewhere unexpected.

| Script | Writes to |
| --- | --- |
| `tools/build_fixtures.py` | `src/fixtures/*.json` |
| `tools/build_diagram.py` | `docs/architecture.png` |
| `tools/build_design_evermind.py` | `docs/gate1/*.docx` |
| `tools/build_summary_group1.py` | `docs/gate1/*.docx` |
| `tools/build_review_benchmark.py` | `docs/reviews/*.docx` |
| `tools/packaging/to_pdf.ps1` | a `.pdf` beside every `.docx` under `docs/` |
| `tools/packaging/build_packages.py` | `dist/*.zip` (creating `dist/` if needed) |
| the agent, once built | `src/out/review_queue.json` — and nothing else |

That last row is the one that matters. **The pipeline writes exactly one
file, and it is not the knowledge base.** See
[`src/contracts/knowledge-base/contract.md`](src/contracts/knowledge-base/contract.md).
